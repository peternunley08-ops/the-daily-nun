# The Daily Nun: shared agent instructions

This repository is the home base for content, assets, posts, strategy, and workflows. Claude Code, Codex, and Antigravity collaborate here. Do not treat another agent's work as disposable or duplicate a claimed task.

## Before writing code or content

1. Read this file and `DISCOVERIES.md`.
2. Check open GitHub Issues and relevant branches or pull requests.
3. Create or claim an Issue. State the agent owner, scope, status, and files involved; a shared GitHub login alone does not identify the agent.
4. Check for overlap before editing. Preserve others' changes.
5. Log useful findings, decisions, unresolved questions, and exact blockers in `DISCOVERIES.md`. Link the Issue.

Use `codex/`, `claude/`, or `antigravity/` branch prefixes and focused pull requests for product changes. Refresh the remote before starting and before pushing. Do not force-push shared branches.

## Current phase and working style

The user has requested discovery and a conversation before further product building. Inventory existing work, suggest concrete options, ask focused questions, and wait for alignment before executing a new product plan. Creating the coordination files and task claims is part of this setup.

Be economical: avoid rereading large files, repeated research, unnecessary delegation, broad rewrites, and long status reports. Before starting a new token-expensive task, describe its approximate steps and wait for confirmation. Record handoff points when context or tooling limits prevent progress.

Claude Code can review long-form writing and strategy; Codex can handle structured implementation, assets, and verification; Antigravity can handle scoped exploration and multi-file iteration. These are suggested responsibilities, not competing claims or automatic delegation. Check Issues first.

## Established product preferences

- Brand: **The Daily Nun**. A plain Peter Nunley byline is acceptable.
- No nickname branding, name-origin story, or decorative personal signature.
- Broad curiosity: government, media, culture, and other subjects.
- Newspaper identity; social content uses minimal words, strong headlines, and one useful idea per post.
- Gen Z relevance is a stated social-content aim. Do not assume every young reader has the same interests or political views.
- Do not invent reporting, quotations, audience metrics, research findings, or platform capabilities. Date statistics, identify denominators, and link sources near significant claims.
- Separate reporting, interpretation, opinion, and corporate or advocacy statements.
- Use gstack `/browse` for all web browsing. Never use `mcp__claude-in-chrome__*`. If browsing is unavailable, record the blocker rather than claiming verification.
- Review dated transactions carefully: an announced deal is not a completed deal.

- `index.html`: newspaper prototype.
- `instagram-launch/`: earlier content studio, opening article, captions, media, source notes, and workflow.
- `stories-current-media/`: six current-media Story designs, copy, and source notes.

Preparing assets is separate from posting to Instagram or TikTok. Check the user's authorization for the actual external action. Do not claim public posting, scheduling, interviews, analytics, or external agent work that did not occur.

Verify changes at the level they require. For site edits, check relevant links, assets, script syntax, and phone layout. For reports, check source/citation integrity, research limits, and the rendered PDF. Do not add tests that merely repeat trivial implementation details.
